# AGENTS.md — для агентов и разработчиков, которые продолжают проект

Прочитай этот файл целиком до первой правки. Он короткий и экономит часы.

## 1. Что это
Telegram Mini App «MMA Simulator»: растишь одного бойца (уход, тренировки, весогонка), каждые 3 дня проводишь карьерный бой по раундам, на Арене асинхронно дерёшься с бойцами других игроков. Монетизация — Telegram Stars (только косметика и «больничный»).

Продуктовые решения и их причины: `docs/01-concept-review.md` (разбор), `docs/05-game-design.md` (механика и баланс). **Не отменяй решения из этих файлов без явного согласия владельца.**

## 2. Карта кода
```
shared/src/        ВСЯ игровая логика. Чистые функции, без I/O, без Date.now() внутри.
  config.ts        все балансные числа, темы, товары
  opponents.ts     лестница соперников, стили, тактики (камень-ножницы-бумага)
  game.ts          состояние бойца, ленивый пересчёт advance(), действия applyAction()
  fight.ts         движок боя по раундам, судьи, итог карьерного боя
  pvp.ts           арена: карточки, боты-спарринги, ELO, лимиты, итог PvP
shared/test/       тесты + симуляция баланса (обязательно зелёные)
server/src/        Hono API + grammY-бот + Stars + напоминания — ОДИН процесс
  routes.ts        HTTP API (/api/*), publicState() — форма ответа клиенту
  fighters.ts      транзакции с блокировкой строки бойца (select … for update)
  arena.ts         подбор соперников, PvP-шаги, уведомление защитнику
  payments.ts      pre_checkout_query (≤10 с!) и successful_payment (идемпотентно)
  reminders.ts     воркер напоминаний: тихие часы, лимит частоты
server/migrations/ SQL-миграции, применяются по порядку (npm run migrate)
web/src/           Preact + htm (без JSX). Экраны в screens/, тема — data-theme + CSS
  api.ts           httpApi (Telegram + сервер) или demoApi (браузер / автономная сборка)
  demo.ts          та же логика из shared/ в localStorage — должна повторять сервер
web/art-src/       арт в base64 (интеграция GitHub не принимает бинарники) → npm run art
tools/             unpack-art.mjs, build-preview.mjs (сборка в один HTML без npm)
```

## 3. Железные правила
1. **Истина — на сервере.** Клиенту не доверяем: состояние, время, исход боя, покупки считает сервер. `initDataUnsafe` не использовать, только проверенный `initData` (`server/src/auth.ts`).
2. **Логика только в `shared/`.** Сервер и `demo.ts` её вызывают, но не дублируют. Новая механика = функция в shared + тест.
3. **Время передаётся параметром `now`.** Внутри shared нет `Date.now()`, иначе тесты и демо-машина времени ломаются.
4. **Детерминизм боя.** Исход зависит от сида и решений игрока. Не добавляй `Math.random()` в движок, используй `mulberry32` с сидом.
5. **Новые поля состояния** добавляй в `PVP_DEFAULTS`/`newFighter` **и** в `normalize()` (`game.ts`): старые сохранения в jsonb должны подниматься без миграции данных.
6. **Изменил баланс — прогони симуляцию.** Целевые значения: умный игрок при 3 заходах в день берёт пояс за 25–35 дней, при 2 заходах — за 40–55. Тест «умный игрок в большинстве случаев берёт пояс за 35 дней» должен проходить.
7. **Stars:** товар выдаётся только в `message:successful_payment`, идемпотентно по `telegram_payment_charge_id`. В `pre_checkout_query` — только быстрые проверки. Внешние оплаты цифровых товаров запрещены правилами Telegram.
8. **Бот не спамит:** не чаще раза в 8 ч (уход) и раза в 2 ч (арена), тихие часы 23:00–09:00 по локальному времени игрока, 403 → `bot_blocked = true`.
9. **Монетизация не продаёт победу.** Нельзя продавать навыки, рейтинг арены, пропуск боёв, лутбоксы за деньги.
10. **Никаких реальных бойцов, логотипов UFC/PFL и похожих лиц.** Только пародийные имена и оригинальный арт.
11. **Боты на арене всегда помечены 🤖 ИИ.** Не выдавать их за людей.
12. **Тексты боя — имена только в именительном падеже**: произвольное имя игрока склонять нельзя («у Вася» — брак).

## 4. Как проверять изменения
```bash
npm install
npm run typecheck      # ни разу не запускался в среде, где писался код (не было npm) — начни с него
npm test               # vitest: логика + баланс + арена
npm run preview        # один HTML с демо-режимом: открой в браузере, пройди сценарий
```
Ручной сценарий после любой правки UI: создать бойца (каждая тема) → тренировка → «К бою» в демо-панели → Tale of the Tape → бой 3 раунда → вердикт → Арена → вызов → бой → рейтинг изменился.

Если npm недоступен (песочница): типы снимает `node:module.stripTypeScriptTypes` (Node 22.7+), см. `tools/build-preview.mjs`. Тесты можно гонять через `node --test` с подменой `vitest`.

## 5. Известные долги (по приоритету)
1. **Не прогнан `tsc` и `vite build`.** Вероятны мелкие ошибки типов на стыках с grammY / postgres / Hono (дженерики `sql<…>`, `tx as unknown as Tx`).
2. **Арена не проверена на живой базе:** `findReal`, лидерборд, `notifyDefender`, deep links `ch_` / `rv_`. Нужен прогон на двух аккаунтах.
3. **Лидерборд** делает `select … limit 50` на каждый заход на арену. При росте закэшировать на 1–5 минут.
4. **Нет античита на мультиаккаунты в PvP** (фарм рейтинга с твинка). Минимум: не давать ELO за бой с одним и тем же соперником чаще раза в сутки, лимит ELO-прироста с одного IP/устройства.
5. **Карточка победы картинкой** (`savePreparedInlineMessage` + `shareMessage`) не сделана, сейчас шер — текст со ссылкой.
6. **Локализация EN** не сделана, тексты разбросаны по экранам. Вынести в `web/src/i18n.ts`.
7. **Автономная сборка** (`window.__STANDALONE__`, GitHub Pages) хранит прогресс в localStorage и «покупает» без оплаты. Это тестовая версия, не прод.

## 6. Чего НЕ делать без согласования с владельцем
- PvP в реальном времени, кланы, турниры с сеткой, второй боец/слоты (обоснование — `docs/01-concept-review.md`, п. 1.1).
- Многоуровневую рефералку.
- Смену стека: Preact+htm выбран ради веса бандла и сборки без плагинов.
- Сжатие арта ниже текущего или его замену на другой стиль внутри темы.

## 7. Метрики
События пишутся в таблицу `events` (`track()` на сервере, `api.event()` на клиенте). Новую фичу без события не выкатывай: SQL-запросы для D1/D7, воронки и ELO — в `docs/03-metrics-and-gates.md`.

## 8. Стиль кода
TypeScript strict, ES-модули, импорты в shared с суффиксом `.js`. Комментарии на русском, только про «почему». Маленькие файлы, одна ответственность. Коммиты на русском, по одной фиче.
